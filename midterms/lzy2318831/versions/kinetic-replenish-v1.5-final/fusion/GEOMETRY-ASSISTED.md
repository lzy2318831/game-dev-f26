# Geometry-assisted LLM v1: acceptance and boundaries

Design: a separate experimental player, not a new game rule or official result.
Relevant existing source-map row: `F8 player boundary | design: RULES F8 |
Episode five methods; fusion/player.py | isolation/public-context tests`.
F2 angle/power and F3 friction remain unchanged. No frozen file may change.

Candidates use detached public state only: integer clockwise screen angles,
radius-22 ball contacts, radius-15 guide clearance, bumper radii, portal entry
exclusion, six public pockets, speed=100+7*power and friction=70. Check paths
again after quantizing the angle. A clear contact is not a guaranteed pot.
Ghost shots additionally require a clear outgoing object path and positive
collision cosine. Power estimates include .99 normal transfer and .88 cushion
loss, not powered-chain prediction. Pocket exposure is screened conservatively.
Banks and device entry routes carry uncertainty notes; exits are not simulated.
An ordinary escape must stop before its first obstacle. If none is supported,
offer minimum-power fallback directions ranked by initial clearance and pocket
exposure, explicitly without a guaranteed clear stop. The LLM must still select
an ID; no baseline/Smart action replaces it. Empty legal/terminal schemas still
produce no candidates.

Acceptance: from cue(230,250), object(700,250), offer angle0 contact with enough
power to cover448 units; never recommend the power15 opening that stops short.
Also check four quadrants, obstructed paths, scratch rays, endpoint legality,
observation isolation and deterministic output. A mocked model selecting candidate
N must execute exactly N; unknown/bool/duplicate/extra-field/non-JSON selections
fail with usage retained and no action. Wrong-seat/terminal schemas yield no
candidates. Existing game validation and call/deadline/cancellation limits apply.

The separate browser entry must display the new identity, keep paid calls off
by default, require existing match consent and record candidates/selection in
its own evidence directory. Offline saved-observation comparison measures route
coverage only, never model performance, actual pots or wins. Preserve old source
and evidence hashes. Independent review follows implementation; student owns gates.

Lifecycle correction: each finished/failed/cancelled match must settle its worker
before a same-origin, current-token POST can prepare another match. It rotates
the token and creates a fresh episode/ledger, never a model request. Fresh
browser consent is required for dispatch. Per-match6/$0.25 and cumulative
server12/$0.50 limits are separate; unknown-cost reservations survive replacement.
The server refuses a fresh start unless its remaining allowance can cover the
whole per-match cap. Failure is not a competitive result. Two complete browser
matches plus error/cancel/timeout/token/cap regressions are required evidence.


Stabilization acceptance: Geometry-only navigation owns exactly one existing
Back button. Its cancellation wait is bounded at 1.5 seconds; navigation may
finish before backend settlement. New-match guards still require a dead old
worker and preserve cumulative reservations. A stuck network response must
never trap navigation or authorize a replacement request. Test the actual
browser on simulation_limit, success, HTTP/selection/timeout/cancel failures and
exhausted cumulative allowance. Failures remain incomplete competitive results.
Contact/bank estimates reserve 15 units of object runout with no additional 4%
launch-speed margin. Omit device-only options when direct contact/pot candidates
exist. These are proposal heuristics, not engine changes or universal safety.

Student-authorized demonstration setting: launcher/server initially prefers2x
candidate power;1x remains a waiting-state selector fallback. Transform only
power to min(100,original_power*multiplier), preserving candidate IDs/angles/
targets/routes. The model selects the ID, including when capping aliases two
actions; metadata must retain the exact selected ID. Record active multiplier
and original power in public requests, trace/consent and call metadata. Label
the accepted scratch tradeoff; base stopping estimates do not guarantee safety
at2x. Only same-origin/current-token waiting-state changes are legal, dispatch
no model request, and cannot reset shared budgets. New matches retain preference
and require fresh consent. Failure/Back settlement rules remain unchanged.

Adaptive energy is a separate optional experiment, never a silent replacement
for1x/2x. Keep their request payloads unchanged. Contact/pot floor25at<=150units,
35at<=350,50beyond; bank+5; max with2x and cap100. Escape/device routes retain2x.
Preserve candidate ID/angle/target/route and strict model selection. Record
power_mode=adaptive and power_multiplier=null (not a fictitious single factor),
original power, floor and formula in requests/traces/consent. The exact-shape
power_mode endpoint uses the same waiting/token/origin/worker/accounting guards.
The current2x initial preference remains; fresh matches retain selected mode.
